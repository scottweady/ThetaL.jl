# Code map

Which functions of `src/` each feature of ThetaL runs. On the left are the two schemes, and below them the options:
kinds of velocity and symbol, integrator features, drivers, and curve utilities. Each option is marked with the
schemes it combines with (2: ETDRK2, 1: ExpEuler). Each setting is a small run, changed from the base case (curve
shortening of a star with ETDRK2, two steps of `advance!`) in that setting only, under line coverage, and the
lines it executes are mapped back to the top-level functions of `src/`. A function is a name in a file, with all
its methods there.

On the right is the package, by directory: `src` (periodic grid functions), `curves` (the state, states from curves,
utilities), `stepping` (symbols, filter, kinematics, schemes, the step), `problem` (the velocity protocol and
`CurveProblem`), `integrator` (the integrator, its edits, checkpoints) and `drivers` (`evolve`, `solve`). Click to
open a directory; each file has one dot per function. A curve joins a setting to every visible row in which it runs
functions that the scheme it was run with does not; the wider the curve, the more functions. Hover over a setting
to see the functions it runs, and over a dot to see the function's name, its docstring and the settings that run it.

```@raw html
<div class="codemap" data-var="CODEMAP" data-src="codemap_data.js"></div>
```

The map shows only what these runs reach: code used only by the tests (the Lawson scheme, kept as a reference)
shows up as not run. It is regenerated by hand after a change to `src/`, so it may lag the code; the date and
commit of the run are under the map. To regenerate it (under a minute; from the package root):

```
julia -t 8 --project=docs docs/codemap.jl
```

## Layout

| Path | |
|:--|:--|
| `src/ThetaL.jl` | the module docstring (equations, conventions, a code map), exports, includes, the precompile workload |
| `src/grid/` | `fourier.jl` (periodic grid functions: wavenumbers, spectral derivative and antiderivative, `double_grid`, `halve_grid`, a trigonometric interpolant), `work.jl` (their work arrays: in-place FFT plans and scratch vectors per N, kept per task) |
| `src/curves/` | `state.jl` (the state and its geometry), `construct.jl` (`from_curve`, `from_arclength_samples`), `measures.jl` (utilities for callers) |
| `src/stepping/` | `symbols.jl` (the rates σ(q) of a curve), `filter.jl` (`SpectralFilter`, `noise_cutoff`), `kinematics.jl` (`thetaL_rhs`, `rigid_part`, `frame_velocity`), `schemes.jl` (`ETDRK2`, `ExpEuler`, their weights), `carried.jl` (the step's part for carried state: transport, combination), `step.jl` (the generic step, `thetaL_step`) |
| `src/problem/` | `evaluation.jl` (`Evaluation`, `StepFailure`, reading the velocity's result), `problem.jl` (`CurveProblem`), `carried.jl` (`CurveField`, `BulkState`: state carried with the curves) |
| `src/integrator/` | `integrator.jl` (`ThetaLIntegrator`, `init`, `advance!`, `step!`), `edits.jl`, `checkpoint.jl` |
| `src/drivers/` | `evolve.jl` (`evolve`, `solve`, `Evolution`, `save_curves`) |
| `ext/ThetaLDotPlotsExt.jl` | `dotplot` of a curve, of curves and of an `Evolution`, loaded with DotPlots (a weak dependency) |
| `examples/` | the scripts of [Examples](@ref), and their environment |
| `test/` | `test_curves.jl`, `test_stepping.jl` (kinematics and schemes), `test_integrator.jl`, `test_drivers.jl`; `common/` |
| `docs/` | this site: `make.jl`, `src/` (the pages), `figures/` (data and plots), `codemap.jl` |

The dependencies run one way: `grid/` ← `curves/` ← `stepping/` ← `problem/` ← `stepping/step.jl` ←
`integrator/` ← `drivers/`. The caller's functions (velocity, symbol, step function, callback) are held as `Any` and
called unspecialized, so one compiled step per scheme serves every curve, velocity and symbol; the kernels are
loops on concrete vectors, which compile with their functions.
